# Stable MCP SDK2 migration candidate

The v0.3.0 candidate uses TypeScript MCP server/client SDK 2.2.0 and the Node
adapter 2.1.0. The published release remains v0.2.2. Node.js 22+ remains the
supported runtime; the separate Python governance package remains dependency
free by default and supports Python 3.11+.

## Existing clients and scientific contracts

All 17 tool names and 16 fixed resource URIs remain available. Input/output
schemas, annotations, defaults, scientific algorithms, coordinate conventions,
qualification policies and schema/policy versions remain unchanged. Older
clients continue to use stdio and stateless Streamable HTTP. The HTTP endpoint
retains its JSON response format, including the older initialize handshake.
Four older HTTP revisions are tested: 2024-11-05, 2025-03-26, 2025-06-18 and
2025-11-25. SDK2 removes the deprecated `execution.taskSupport: forbidden`
catalog metadata; this server never provided Tasks execution.

The scientific contracts remain on Zod 3. A public Standard Schema adapter
retains the released Zod validation behavior and Draft 7 JSON Schema conversion,
including separate input/output conversion. SDK2's internal Zod 4 dependency
is isolated from these contracts. Benchmark goldens and contract schemas are
not regenerated by this migration.

Modern clients negotiate 2026-07-28 using `server/discover`. Catalog responses
carry private 60-second cache hints. Scientific tool results and resource
contents receive no reusable cache lifetime. Tools continue to return structured
content and their JSON text envelope. The SDK's modern metadata is additive.

## Operators and Python users

The `/mcp` and `/health` paths and all existing configuration variables remain
supported. HTTP still defaults to loopback, accepts bounded POST messages,
validates Host and Origin, and enforces the existing bearer token and rate
limits. Non-loopback bindings still require an explicit Host allowlist and
`EPIMCP_AUTH_TOKEN`. No client is granted additional filesystem access.
Modern requests use fresh server instances, preserving isolation between
clients whose JSON-RPC request IDs collide.

The legacy Python `analysis-compat` extra remains available with its historical
SDK1 bound. It does not implement the active TypeScript MCP server. Upgrading
the Python governance package does not force an MCP Python SDK major upgrade.

## TypeScript embeddings and review

The SDK now exposes separate `@modelcontextprotocol/server`,
`@modelcontextprotocol/client` and `@modelcontextprotocol/node` packages. Direct
embeddings using SDK1 imports need migration. The public `startServer`,
`createEpigenomicsMcpServer` and HTTP entrypoints remain available. Directly
connecting the factory to an old-style transport serves the legacy protocol;
use the shipped entrypoints for modern protocol negotiation.

`npm run test:protocol -- --output-dir /tmp/epimcp-clients` exercises actual
SDK1.31 and SDK2.2 clients over stdio and HTTP. CI repeats this against an npm
tarball installed outside the checkout on Node.js 22 and 24. The gate verifies
the released catalog fingerprint and exact application results across all four
combinations, after checking modern envelope metadata. A test-only launcher
controls application clocks and generated IDs; production entrypoints never
import it. Nineteen pre-version-bump application results also exactly matched
the released source server.

This candidate publishes no package or hosted service. Review its CI results
before release, and retain v0.2.2 plus the prior container digest for rollback.
SDK2 does not automatically add MCP Apps, elicitation workflows or new
scientific capabilities.
